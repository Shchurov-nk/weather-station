# Дальнейшие планы — обзорно, с вариантами

Снимок на 2026-08-12. Сделано: фазы 0–2 (схема в git, docker-стек, усиленный
API), приёмка прогнана локально, runbook написан. Дальше — по убыванию
приоритета. У каждого шага перечислены варианты решений; ✦ — вариант,
выбранный или рекомендуемый по умолчанию.

## 1. VPS: перенос стека (фаза 3)

Цель: стек работает на 193.124.115.214, HTTPS, данные текут с датчика.

- **Домен**
  - ✦ DuckDNS — бесплатно, свой лимит Let's Encrypt (решено ранее)
  - Купленный домен — красивее для портфолио; замена = одна строка в `.env`
  - sslip.io — ноль усилий, но общие LE-лимиты, для постоянной работы не годится
- **Кто выполняет**
  - ✦ По runbook руками — максимум обучения
  - Claude по SSH с комментариями каждого шага — быстрее, обучение по логу
- **Патч прошивки-«мостик»** (HTTPS + токен) — без вариантов, описан в runbook §8.

## 2. Бэкапы (фаза 4)

Цель: ночной дамп + копия вне VPS + доказанное восстановление.

- **Куда уходит копия**
  - ✦ Pull по rsync с домашней машины — VPS не имеет ключей ни к чему
  - rclone с VPS в объектное хранилище (Backblaze B2/S3) — если домашняя
    машина не всегда включена; минус: ключ хранилища лежит на VPS (сузить права до write-only)
  - Оба сразу — дёшево, покрывает оба риска
- **Контроль, что бэкап жив**
  - ✦ healthchecks.io ping в конце скрипта (уже заложено в backup.sh)
  - Проверка свежести файла на домашней стороне cron-скриптом
- **Restore-тест**: раз в квартал в одноразовый контейнер — без вариантов,
  это и есть приёмка.

## 3. Streamlit-дашборд (фаза 5)

Цель: графики температуры/влажности/давления с выбором диапазона.

- **Инструмент**
  - ✦ Streamlit — выбран осознанно (обучение, портфолио)
  - Grafana — 15 минут и алертинг из коробки, но ноль переносимого кода (отложено)
  - Plotly Dash — гибче Streamlit, но больше кода на тот же результат
- **Графики**
  - ✦ plotly — интерактивность из коробки, знаком любому DS
  - altair — декларативный, красивый, чуть беднее интерактив
- **Данные для разработки** (датчик ещё не шлёт)
  - ✦ `scripts/seed_fake_data.sql` на `generate_series` с суточной синусоидой
  - Ждать реальных данных — теряем темп
- **Агрегация**
  - ✦ `date_trunc` + `avg()` в SQL, гранулярность зависит от диапазона
  - Тянуть сырые строки в pandas — антипаттерн при росте данных
- **Доступ**
  - ✦ Публичный read-only дашборд (данные не секретны)
  - `basic_auth` в Caddyfile — одна строка, если захочется закрыть
- Обязательный элемент: «last reading N min ago» крупно — это бесплатный
  мониторинг живости датчика. `/table` после запуска дашборда удалить.

## 4. Прошивка по-взрослому (фаза 6)

Цель: воспроизводимая сборка и отсутствие дыр в данных при обрывах связи.

- **Сборка**
  - ✦ PlatformIO с пиннингом версий в `platformio.ini` (та же идея, что uv.lock)
  - Остаться на Arduino IDE — версии библиотек нигде не зафиксированы (текущая боль)
- **Устойчивость** (делать по нарастающей)
  1. reconnect WiFi + проверка httpCode — просто и закрывает 80% проблем
  2. ✦ кольцевой буфер в RAM (~512 записей ≈ 8 ч) + дослать при восстановлении
  3. буфер в NVS/flash — переживает перезагрузку, но износ флеша и сложность; только если отключения длинные и частые
- **Метка времени измерения**
  - ✦ NTP на ESP32 + поле `measured_at` (миграция 003, `COALESCE` в запросах)
  - Оставить серверное `reading_time` — проще, но досланные из буфера строки получат неверное время
- **ArduinoJson v7**: `StaticJsonDocument` → `JsonDocument` (v6 устарел).

## 5. CI (фаза 7)

Цель: каждый push проверяется автоматически.

- **Проверки**
  - ✦ GitHub Actions: ruff + pytest; миграции прогоняются против
    service-контейнера Postgres — заодно тест схемы на чистой БД
  - Pre-commit хуки локально — дополнение, не замена
- **Деплой**
  - ✦ Пока: `git pull && docker compose up -d --build` на VPS
  - Потом: сборка в CI → образ в GHCR → `docker compose pull` на VPS.
    Триггер для перехода: сборка стала мучить VPS (1 ГБ RAM) или надоело
    держать исходники на сервере
  - Watchtower/автодеплой по push — не рекомендую: магия без наблюдателя
- Можно поднять lint+pytest раньше фаз 3–4 — дёшево и сразу страхует.

## 6. Мелочи, не привязанные к фазам

- **LICENSE** — ✦ MIT для портфолио-репозитория.
- **Postgres 17 → 18** — когда-нибудь; путь: pg_dump → pg_restore (тома
  мажорных версий несовместимы). Спешки нет.
- **Сеть Docker на этой машине** (хост↔контейнер не ходит):
  - ✦ Жить с обходом (`docker build --network=host`, тесты из контейнера)
  - Продиагностировать с sudo (nft ruleset, backend iptables/nftables) — час-два
  - Подождать обновлений Docker/Ubuntu 26.04 — вероятно, починят
- **Групповой доступ к docker** — после следующего logout/login костыль
  setfacl не нужен.

## 7. Сознательно отложено (и когда возвращаться)

| Технология | Вернуться, если |
|---|---|
| TimescaleDB | запросы по годам данных станут заметно тормозить (при 525k строк/год — нескоро) |
| MQTT | датчиков станет несколько или появится двусторонняя связь |
| Grafana | понадобится алертинг по метрикам, а не «глазами на дашборд» |
